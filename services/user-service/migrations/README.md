# Миграции user-service

Файл применяется один раз по числовому префиксу, порядок — лексикографический
(`pkg/migrate`). Имя должно подходить под `^(\d+)_.+\.sql$`; всё остальное
(включая этот README) раннер не видит.

## Главный запрет: применённый файл не редактируется

`pkg/migrate` кладёт в `schema_migrations` SHA-256 каждого файла и при старте
сравнивает его с содержимым на диске. Несовпадение — ошибка запуска:

```
migrate: 001_init changed after it was applied (stored ..., on disk ...): add a new migration instead
```

Поэтому **правка уже применённой миграции — это сломанный старт во всех
окружениях**, где она прошла (включая свежую базу из `docker-compose.yml`).
Правда, которую нужно донести, ездит в новой миграции или в документации, но не
в старом файле.

## `001_init.sql`: шапка устарела и останется устаревшей

Шапка `001_init.sql` описывает типы колонок как след поддержки PostgreSQL 9.3.
Это исторический факт на момент написания файла, а **не** описание текущей
схемы: сервер — `postgres:17` (Issue #35).

Шапка не поправлена намеренно — см. запрет выше. Актуальное описание живёт:

- в `002_document_schema.sql` — как `COMMENT ON`, то есть внутри каталога БД
  (`\d+ users` в `psql`);
- ниже — как обоснование решений по типам.

## Почему типы такие, какие есть (на PG 17)

| Колонка | Решение | Основание |
| --- | --- | --- |
| `users.id` | UUID без `DEFAULT gen_random_uuid()` | `domain.NewUser` присваивает идентификатор при сборке агрегата: id нужен **до** вставки — для создания сессии и для ответа на `POST /v1/users`. `DEFAULT` перенёс бы решение в `INSERT` и добавил `RETURNING`-раундтрип за значением, которое валидно заранее. |
| `users.email` | `VARCHAR(254)`, без `CITEXT` | Адрес нормализуется в домене (`internal/domain`) до записи, поэтому уникальный индекс сравнивает уже сравнимые значения. `CITEXT` перенёс бы правило в БД, изменил бы семантику уникальности и добавил зависимость от contrib — ради инварианта, который домен уже обеспечивает. |
| `users.phone` | `VARCHAR(20)`, без расширений типов | Формат проверяет домен; расширение типов не требуется. |

Отдельно: `book-service` объявляет `DEFAULT gen_random_uuid()` в своей схеме, но
его postgres-репозиторий ещё не написан (сервис на in-memory), а домен
`book-service` тоже генерирует UUID сам. Как рабочий прецедент это не считать.

## Как править схему дальше

1. Новый файл `NNN_что_то.sql` со свободным числовым префиксом.
2. Идемпотентность к уже существующей схеме обязательна: у кого-то миграция
   пройдёт поверх старой базы, у кого-то на чистой.
3. Проверить на обеих: чистая база (`docker compose down -v user-db` +
   `up -d`) и база с применённой `001`.
