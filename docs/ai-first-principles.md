# AI-first принципы

Документ фиксирует подход к интеграции AI в Smart Library. В отличие от «AI в конце» (chatbot поверх готового продукта), AI здесь — первоклассный компонент архитектуры с первого дня.

## 1. AI как часть домена, а не надстройка

Рекомендации книг — не отдельный чат-бот, а часть предметной области. Каждый сервис предоставляет gRPC-API — фронтенд и AI-модуль вызывают их независимо.

AI-сервис (ai-assistant/) — отдельный микросервис с собственным REST/gRPC-интерфейсом. Не имеет прямого доступа к БД других сервисов — все данные поступают через контракты с авторизацией.

## 2. RAG для точности, LLM для генерации

RAG (Retrieval-Augmented Generation) обеспечивает фактическую точность: семантический поиск по каталогу книг через векторную БД, результаты конкатенируются в контекст для LLM.

LLM отвечает за формулировку рекомендаций, объяснений и диалог с пользователем. Не имеет прямого доступа к данным — только через RAG-слой.

### Выбор модели

Критерии выбора модели: качество на целевых сценариях, стоимость инференса, latency, требования к данным (PII → локальная модель или облако с DPA), поддержка tool-calling и контекстного окна.

## 3. Версионирование промптов

Каждый промпт хранится как отдельный файл в ai/prompts/ с номером версии в имени: recommend-books-v2.txt.

История изменений ведётся в git — промпты обновляются так же, как код.

A/B-тестирование — разные версии промптов могут работать параллельно для оценки качества.

## 4. Оценка качества (eval)

Тестовые сценарии в ai/eval/ — набор вопросов/ожиданий для проверки релевантности рекомендаций.

Метрики: precision@k, recall@k, MRR (Mean Reciprocal Rank) для поисковых сценариев; human eval для диалоговых.

Регрессия: при обновлении модели или промпта eval-набор прогоняется автоматически — падения качества блокируют деплой.

### Cost tracking

Контроль стоимости инференса: токены на запрос, кеширование повторяющихся запросов, batching. Метрика — стоимость рекомендации на пользователя (unit-экономика инференса).

### Observability

Трейсинг цепочек вызовов (LLM → RAG → LLM), логирование промптов и ответов для разбора инцидентов. Метрики качества в проде: доля отказов, latency, стоимость запроса.

## 5. Безопасность и приватность

AI не имеет прямого доступа к БД — все данные через gRPC-API с авторизацией и валидацией.

Промпты не содержат пользовательских данных без явного согласия.

PII фильтруется на входе в RAG-слой перед отправкой в LLM.

### Guardrails и защита от prompt injection

Guardrails: проверка выхода LLM на соответствие политикам (запрет на медицинские/юридические советы, фильтрация небезопасного контента).

Защита от prompt injection: валидация входных данных, изоляция системных промптов, ограничение инструментов, доступных агенту.

### Human-in-the-loop

Критичные рекомендации (например, для библиотекарей) проходят через подтверждение человеком перед публикацией. Границы автономности AI определяются сценарием: где AI предлагает, а где решает человек.

### Fallback-сценарии

При недоступности LLM или низком качестве ответа — возврат к классическому поиску по каталогу. AI не должен быть single point of failure для критичных сценариев.

## 6. Структура проекта

```
ai-assistant/          # AI-сервис (gRPC/REST)
  ai/
    prompts/           # версионируемые промпты
    rag/               # векторный поиск, эмбеддинги
    eval/              # тестовые сценарии, метрики
  cmd/                 # точка входа
  internal/            # логика
  pkg/                 # публичные контракты
```

## 7. Принципы принятия решений

| Ситуация | Принцип |
| --- | --- |
| Новый AI-фич | Начинается с доменного контракта (proto), не с модели |
| Точность vs. креативность | Точность через RAG, креативность через LLM-промты |
| Обновление модели | Прогон eval-набора обязателен перед деплоем |
| Промпт-инжиниринг | Промпты в git, ревью как для кода |
| Данные пользователя | Только через авторизованные контракты, PII фильтруется |
| Стоимость инференса | Кеширование, batching, выбор модели под задачу |
| Безопасность | Guardrails, защита от prompt injection, human-in-the-loop |
| Отказ LLM | Fallback на классический поиск, AI не single point of failure |
