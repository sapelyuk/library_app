# AI-first принципы

Документ фиксирует подход к интеграции AI в Smart Library. В отличие от
«AI в конце» (chatbot поверх готового продукта), AI здесь — **первоклассный
компонент архитектуры** с первого дня.

## 1. AI как часть домена, а не надстройка

- **Рекомендации книг** — не отдельный чат-бот, а часть предметной области.
  Каждый сервис предоставляет gRPC-API — фронтенд и AI-модуль вызывают их
  независимо.
- **AI-сервис** (`ai-assistant/`) — отдельный микросервис с собственным
  REST/gRPC-интерфейсом. Не имеет прямого доступа к БД других сервисов —
  все данные поступают через контракты с авторизацией.

## 2. RAG для точности, LLM для генерации

- **RAG (Retrieval-Augmented Generation)** обеспечивает фактическую точность:
  семантический поиск по каталогу книг через векторную БД, результаты
  конкатенируются в контекст для LLM.
- **LLM** отвечает за формулировку рекомендаций, объяснений и диалог с
  пользователем. Не имеет прямого доступа к данным — только через RAG-слой.

## 3. Версионирование промптов

- **Каждый промпт** хранится как отдельный файл в `ai/prompts/` с номером
  версии в имени: `recommend-books-v2.txt`.
- **История изменений** ведётся в git — промпты обновляются так же, как код.
- **A/B-тестирование** — разные версии промптов могут работать параллельно для
  оценки качества.

## 4. Оценка качества (eval)

- **Тестовые сценарии** в `ai/eval/` — набор вопросов/ожиданий для проверки
  релевантности рекомендаций.
- **Метрики:** precision@k, recall@k, MRR (Mean Reciprocal Rank) для
  поисковых сценариев; human eval для диалоговых.
- **Регрессия:** при обновлении модели или промпта eval-набор прогоняется
  автоматически — падения качества блокируют деплой.

## 5. Безопасность и приватность

- **AI не имеет прямого доступа к БД** — все данные через gRPC-API с
  авторизацией и валидацией.
- **Промпты не содержат пользовательских данных** без явного согласия.
- **PII фильтруется** на входе в RAG-слой перед отправкой в LLM.

## 6. Структура проекта

```
ai-assistant/          # AI-сервис (gRPC/REST)
  ai/
    prompts/           # версионируемые промпты
    rag/               # векторный поиск, эмбеддинги
    eval/              # тестовые сценарии, метрики
  cmd/                 # точка входа
  internal/            # логика
  pkg/                 # публичные контракты
```

## 7. Принципы принятия решений

| Ситуация | Принцип |
|----------|---------|
| Новый AI-фич | Начинается с доменного контракта (proto), не с модели |
| Точность vs. креативность | Точность через RAG, креативность через LLM-промты |
| Обновление модели | Прогон eval-набора обязателен перед деплоем |
| Промпт-инжиниринг | Промпты в git, ревью как для кода |
| Данные пользователя | Только через авторизованные контракты, PII фильтруется |
